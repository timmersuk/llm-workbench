# Knowledge layer adopts the Open Knowledge Format (OKF) instead of a bespoke schema

The Knowledge layer needed an on-disk format for durable concept documents (coding standards, architecture decisions, domain notes) before any store existed to parse them. We adopted the [Open Knowledge Format (OKF) v0.1](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md) — markdown files with YAML frontmatter organized into a directory bundle — rather than inventing a bespoke schema, per the "prefer open standards" invariant: it's readable and diffable with no tooling (`cat` a file), git-native (reviewable as normal pull requests), portable (a bundle is just a directory, no API or service lock-in), and minimally opinionated (only `type` is required), so it won't need to be re-specified as the kinds of knowledge this project captures evolve.

Considered keeping Knowledge in the same flat `<root>/<id>/<kind>.yaml` shape already used for Task and Project — rejected because that shape is built for terse, structured fields, not the free-form, cross-linked, citable prose that long-lived knowledge documents need, which is what OKF's markdown-plus-frontmatter model is designed for.
