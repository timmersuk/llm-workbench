# Structure `context.yaml`'s `files` entries as `{path, role}` instead of bare path strings

`context.yaml`'s `files: []` field has been a plain `[]string` of repo-relative paths since Milestone 4 — just naming which files matter to a task, with no room to say why. In practice that room got taken anyway: `frontend/src/GrillMePanel.tsx`'s `normalizeRequirementsDraft` was added specifically to repair `{path, role}` objects a live GrillMe turn had proposed for `files` despite the tool's schema demanding bare strings, and independently, five hand-authored `context.yaml` files in the data repo (`docker-and-ci`, `e2e-tests`, `frontend-unit-tests`, `windows-background-service`, `windows-systray-icon`) used the same `{path, role}` shape rather than the six other tasks' plain strings — both a live model and a Claude Code session working directly on files converged on the same richer shape independently, without coordinating.

We widened `Files` from `[]string` to `[]ContextFile{Path, Role string}` (`internal/task/context.go`), same precedent as docs/adr/0008's `VerificationStep` widening: turn the bare entry into a structured object rather than add a side-channel or infer the missing information heuristically later. `Role` is optional (`omitempty`) — a file worth listing doesn't always need an explanation, and the six pre-existing plain-string tasks were migrated with `role` simply absent rather than a fabricated rationale invented after the fact.

This touches every layer the same way docs/adr/0008 did: `RequirementsDraft.Context.Files`, `drafttool.ProposeContext`'s JSON schema, `FinalizeRequirements`'s trimming (`internal/task/lifecycle.go`, now via `trimmedContextFiles`), the frontend's `TaskContext`/`RequirementsDraftForm` (files become a repeatable path+role row, mirroring the existing verification-step rows), and every existing `context.yaml` in the data repo — both populations (plain-string and already-object-shaped) were migrated to the same final shape in one pass, rather than leaving the schema tolerant of both indefinitely. `GrillMePanel.tsx`'s `normalizeRequirementsDraft` stays, but flips direction: it now upgrades a bare path string a model might still emit into `{path, role: ''}`, instead of downgrading an object to a bare path.
